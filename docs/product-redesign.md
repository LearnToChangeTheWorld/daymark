# 信息结构与界面改版

目的：打开软件就知道要做什么；查看原文和管理采集时再展开细节。

| 入口 | 内容 | 保留规则 |
| --- | --- | --- |
| 待办 | 合并原“今天”入口；手动确认或关键词明确识别的全部未完成事项，按原消息日期倒序分组 | 已读、逾期、较远截止日期和无截止日期均保留，完成后进入记录 |
| 待确认 | 有行动线索，但具体事项或适用对象仍不明确的消息 | 确认后加入待办；排除后保留原文 |
| 通知 | 学习事项通知，按作业提交、考试考务、课程安排、报名材料筛选 | 默认近 7 天，可查看更早通知 |
| 记录 | 全部已采集原文、较低相关内容、已完成、归档 | 可搜索和查看上下文 |

待办、待确认和记录列表显示标题、来源和时间；待办突出显示原消息的年月日及星期，行内显示收到消息的时刻，截止日期另行标注。日期统一按北京时间计算；历史补读仍放在微信、QQ等来源中的原日期，不使用导入日期，未知原日期单列，手动事项使用记录时间。通知列表直接展开完整正文，课程、任务/考试名称和时间分行呈现，不截断正文。平台泛化标题改用正文里的具体名称，没有读到正文时明确提示；原文与操作入口保留。主导航不再按学业、生活划分。人工确认的待办始终保留，不由相关性规则撤销。

待确认每条消息的“确认”旁直接显示“归档”，无需打开详情。各列表可进入“批量归档”，此时才展示复选框和全选操作；全选仅限当前结果，切换搜索或筛选后清除旧选择，新消息不自动选中，避免处理隐藏内容。批量保存为原子操作，成功显示数量，失败保留选择供重试；原文、已读和完成状态保留。在“记录 → 已归档”提供单条取消归档与批量恢复。

明确布置的作业（如“本周作业：课本第 3 章 1—5 题”），以及具体事项含有指令或时间要求（如“请大家填写问卷”“周五前提交实验报告”），自动持久保存为待办；已有待确认也按相同规则处理。指定他人、仅限某类学生、自愿报名、泛泛提醒、疑问、完成回执、取消及附件占位文字不会直接加入。原文和已读状态保留，不凭采集日期猜截止时间；缺截止日期时显示“截止日期待确认”，仍按原消息日期分组。同群同日相同要求合并，接龙续报不重复创建。自动待办详情注明依据，可点“不是待办”纠正，后续重复采集和重启不恢复已排除事项。

QQ、微信登录后自动发现群聊。先用群名和学习通课程名判断；模糊群分批检查近 7 天少量可读消息，只有判为学习相关的群才持续采集。生活社交群淡化，不进入主要页面。不能判断或读取失败必须显示原因；允许纠正误判，无需用户完成选群步骤。每 10 分钟重新发现群聊，保留账号隔离与历史补读检查点。图片、附件内容当前仍未识别。

## 2026-10-16：视觉与列表布局调整

主要参考 [shadcn/ui GitHub 仓库](https://github.com/shadcn-ui/ui)，具体查看 [Tasks 示例](https://ui.shadcn.com/examples/tasks) 和 [Sidebar 组件布局](https://ui.shadcn.com/docs/components/sidebar)。Tasks 的工具栏、对齐列表与显式批量选择适合本项目的事项处理；Sidebar 的导航分组、内容区、底部设置适合区分事项与来源管理。另查看 [Plane](https://github.com/makeplane/plane)、[Memos](https://github.com/usememos/memos) 与 [AFFiNE](https://github.com/toeverything/AFFiNE)；本轮以 shadcn/ui 的列表与侧栏思路为主要参考。

| 位置 | 在 Daymark 中的实现 |
| --- | --- |
| 品牌与侧栏 | 删除名称下的“学生事项工作台”；只显示 Daymark。固定四个事项入口，来源管理单独分组，服务状态与设置放在底部 |
| 页面结构 | 浅灰工作区、白色列表面板；页标题、工具栏和列表采用同一宽度，减少四处分散的边界 |
| 列表工具栏 | 搜索与批量操作在固定位置；记录筛选使用分段按钮，时间和主题筛选在其下方 |
| 日期与事项 | 原消息日期作为分组标题；标题、来源与时间分层，截止时间单独显示；桌面标题最多两行，手机最多三行，完整原文在详情中查看 |
| 操作 | 待办保留“已完成”文字按钮；待确认的“确认 / 归档”并排常显，批量操作单独进入选择模式 |
| 通知阅读 | 直接展示完整正文和来源时间，保持换行、不设正文截断或内部滚动框 |
| 手机 | 四入口底部导航；原消息时间与操作放到标题下方，320px / 390px 宽度不横向溢出 |
| 登录与反馈 | 表单、扫码、补读结果沿用真实状态；成功、部分失败和失败保持不同反馈颜色 |

以上是布局和信息层级参考；页面 HTML/CSS 为本项目自行实现，原生 JS 和接口保持兼容。控制层继续使用本地 [Tabler](https://github.com/tabler/tabler) 1.6.1（MIT），其依赖版本、校验值和许可证在 `public/vendor/tabler/`。没有引入 shadcn/ui React 组件或远程字体、CDN。


验证：群名/消息分类、自动发现与纠正、跨账号隔离、发现失败保留有效连接；桌面和手机四个入口、原文详情与完成/候选处理；原消息日期分组、跨年、北京时间午夜、历史补读与未知日期、截止日期编辑不改变分组；现有登录和历史补读回归。

本轮界面验证：完成与恢复、单条/批量归档、完整通知、登录与补读结果四组 Playwright 检查通过；用示例数据检查四个页面在 320、390、768、1024、1280、1440、1920px 下无页面和列表横向溢出。操作测试使用模拟 API，不修改真实事项，不代表重新验证平台登录或采集能力。
