# 安装与平台接入

当前版本只在 Windows 本机使用，界面在浏览器打开。先按 [README](../README.md) 启动服务并输入软件访问码。雨课堂和教务系统尚未适配，不能通过填写账号完成接入。

## 数据保存在哪里

默认目录为 `%LOCALAPPDATA%\StudentInbox`。事项与原消息会保存到本机，连接平台时仍需要联网。Windows 账号密码、Cookie 和微信读取密钥使用当前 Windows 用户的 DPAPI 加密；事项正文、消息缓存和部分运行文件不是整库加密。

开发或备份可指定其他目录，例如：

```powershell
$env:STUDENT_INBOX_DATA_DIR = 'D:\DaymarkData'
node server.mjs
```

重启时使用同一目录即可恢复事项和保存的连接设置。访问码在该目录的 `access.token` 中，也会在启动窗口显示；不要把它当作平台密码，或公开在截图里。不要把整个数据目录上传到 GitHub。

## 微信

1. 安装官方 Windows 微信和 Python 3.10 x64，运行 `tools/setup-chat.ps1 -Component WeChat`（完整 PowerShell 命令见 README）。
2. 点击“接入账号 → 微信”，打开微信登录窗口。使用手机微信扫码并确认，或进入客户端已保存的账号。
3. 首次点击“初始化消息读取（重启一次微信）”。该操作会重启一次客户端，在本机获取并校验本账号数据库读取密钥；密钥经 DPAPI 加密保存，不返回到网页或日志。
4. 自动识别学习相关群，并补读近 7 天电脑已缓存的消息。接入面板显示群识别、补读和采集状态；完成后显示“微信连接成功”和“完成，返回事项”。
5. 保持微信与本机事项服务运行。以后启动服务会静默恢复已有设置；需要重新登录时再手动打开登录窗口。

默认读取本机数据库，不需要逐群打开聊天窗口；免打扰群也可读取。每 4 秒轮询，每批最多检查 12 个群，群较多时轮换检查。已在微信 4.1.15.53 上验证群列表、免打扰群缓存、原消息时间和重复读取去重，其他版本可能需要调整。

本机没有缓存的手机消息不能凭空补齐。“已连接”表示本机消息库可读，不保证官方客户端一直在线。图片、语音及附件正文尚未理解；分享卡片只提取可识别文字。客户端升级、读取密钥变化或库文件不可用时，需要按面板原因处理。

如果官方客户端出现“进入微信”，初始化会尝试定位这个按钮；扫码与手机确认仍需本人完成。若初始化失败，不要反复点击：先检查客户端是否已进入聊天界面、Python 组件是否安装，再查看面板错误。不要在公开 Issue 附带本机数据库或读取密钥。

## QQ

1. 安装官方 Windows QQ，运行 `tools/setup-chat.ps1 -Component QQ`，另外下载并校验 NapCat v4.18.38。其许可独立于 Daymark，见 [第三方说明](../THIRD_PARTY_NOTICES.md)。
2. 点击“接入账号 → QQ → 生成登录二维码”，使用手机 QQ 扫描并确认。组件启动专用本机进程，自动配置消息通道。
3. 登录后自动识别学习群，分页补读近 7 天可取得的历史，并持续接收新消息。
4. 接入面板显示补读进度、最近检查和采集时间。已接入群补读完成且采集正常后，显示“QQ连接成功”；没有新消息也可完成接入。

NTQQ 管理底层登录凭据，Daymark 保存自动连接及群识别设置。已在本机验证扫码、历史读取和重启恢复；平台验证、客户端版本和网络变化仍可能要求重新扫码。实时消息、免打扰和断线期间的完整性还需要更多真实环境验证。

历史按稳定消息 ID 与实时消息去重，失败保留进度重试。每轮每群最多 200 页；组件没有提供更早消息时会提示范围无法确认完整，不把“读到最后一页”直接当作“全部历史”。

## 自动识别群与保存设置

微信、QQ 都依据群名、已接入课程名及模糊群的少量近期文字识别学习群，每 10 分钟重新检查。生活社交内容淡化，无法确定的群保持待识别。可以展开识别结果纠正“应当采集”或“不必采集”；纠正按平台账号隔离保存。

不保存私聊；未接入群用于识别的少量消息预览仅保留在内存中，不进入事项库。采集位置在消息耐久保存后推进，重复补读保留用户已经做出的完成、归档和排除决定。

“保存连接”指保存本软件设置，底层登录状态由对应客户端管理。断开本软件采集会停止自动连接，不会代替在官方客户端退出账号。部分失败或登录失效时不显示接入完成；手动“检查采集状态”会显示完成或失败结果，不会反复打开登录窗口。

## 学习通

1. 点击“接入账号 → 学习通”，填写本人手机号和密码，再点“登录并开始同步”。目前没有学习通扫码入口。
2. 可勾选在这台 Windows 电脑保存账号并自动登录。账号与 Cookie 经 DPAPI 保存于数据目录；不勾选时仅在本次进程内保存。网页不返回密码或 Cookie。
3. 查看课程、未提交作业、近 7 天通知及异常明细。服务运行时每 5 分钟检查，也可立即同步；重启恢复 Cookie，失效时用保存的账号尝试重新登录。
4. 如被验证码拦截，点“打开学习通验证窗口”，由本人在独立 Edge 窗口完成验证，再点“已完成验证，继续同步”。该窗口需要保持打开，以继续使用验证后的会话；不自动绕过验证码。

读取通过 HTTPS。通知保留平台发布时间；时间未知时明确标注，不使用采集时间伪装。分页到 5 页仍未覆盖近 7 天时提示未读全。已提交或待批阅作业不再新增，但已导入待办暂不会跟随平台自动完成。截止时间缺少年份时保留原文、等待确认。

账号文件保存在 `accounts/chaoxing.dpapi`；采集到的事件先进入本机 outbox，事项库确认保存后移除。断开账号删除加密账号文件，保留已采集事项。账号管理接口只接受已登录的本机访问，未来云端模式不能直接提交平台密码。

## 事项与消息的区别

- 明确作业、提交、填写等具体行动要求自动加入待办，详情可查看依据并点“不是待办”纠正。
- 有具体事项、适用对象仍不清楚的进入待确认；只有 @名单、闲聊或空泛催促保留在记录。
- 通知直接展示正文，可人工加入待办；没有取得正文时会说明，不用泛化标题冒充详情。
- 待办按原消息的北京时间日期分组；补读旧消息仍归原日期，截止时间单列。未知时间单列显示。
- 点击“已完成”后显示保存结果；单条归档在确认旁，批量归档只处理明确选中的记录。可以在记录中恢复。

分类不调用 LLM，不能理解全部语境；没有候选不代表没有作业。目前没有系统推送或定时提醒，请主动查看仍未完成的事项。

## 独立采集端与网站接口

独立上传队列及 OneBot webhook 保留用于后续扩展；它与上述本机集成接入不是同一个安装步骤。事件格式、鉴权、上传重试和未来部署边界见 [网站接口说明](website-interfaces.md)。当前不需要运行 Docker、配置域名或开通校园网入站端口。
